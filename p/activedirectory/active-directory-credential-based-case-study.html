Classic Credential-Based Active Directory Intrusion — Full EchoSentinel Reconstruction

This case study documents a multi-stage Active Directory intrusion that begins with anonymous share reconnaissance and progresses through Kerberos abuse, service-account compromise, remote execution, credential dumping, ACL abuse, replication-right activity consistent with DCSync, and late-stage privileged operations involving Administrator ticket activity. The page is built from the EchoSentinel screenshots, the markdown write-up, and the scenario notes package.

Attack Narrative

Phase logic

The sequence is internally coherent. Anonymous network/share activity appears first. That is followed by Kerberos activity for j.smith, then RC4 service ticket requests consistent with Kerberoasting. Successful NTLM validation is then visible, after which the attacker pivots into authenticated use of Bobo. Remote execution and persistence follow, then direct credential dumping against LSASS. After that the telemetry shifts into privilege manipulation, machine-account context, DS replication-style object access, and finally Administrator ticket activity.

What matters operationally

No single event proves the entire intrusion. The strength comes from chaining the telemetry: 4624/5140/5145 establish recon, 4769 establishes roasting behavior, 4776 validates cracked or otherwise recovered credentials, 4688/4697/4698 prove execution and foothold actions, 4663 proves LSASS access, 4670 marks permission abuse, and replication-related 4662 events support DCSync. EchoSentinel alerts line up with the same progression and provide a clean analyst pivot path.

Phase-by-Phase Attack Chain

1

Network reconnaissance and service enumeration

Anonymous network logon and SMB/share access from 192.168.1.13 appear first. Relevant telemetry includes 4624 LogonType 3, 4627, 5140, and 5145.

  • Observed user: ANONYMOUS LOGON
  • EchoSentinel signal: Alert 856 / ES-LAT-001
  • Interpretation: anonymous probing of file/share exposure on a domain-connected Windows host
2

Kerberos abuse and roast preparation

Kerberos TGT and service ticket requests are visible for j.smith, with RC4 service ticket requests against likely roastable accounts and SPNs.

  • Events: 4768 and 4769
  • Targets seen: Bobo, vagran, j.smith
  • EchoSentinel signal: Alert 858 / ES-AD-001 Kerberoasting indicator (4769 RC4)
3

Password cracking and credential validation

Successful 4776 events indicate NTLM validation. One screenshot explicitly shows j.smith validated from workstation kali. Later Bobo is validated successfully.

  • Critical field: Status 0x0
  • Analytic value: proof that the credential is not just harvested but usable
  • Correlation: successful validation flows directly into authenticated network logon
4

Service account compromise

Bobo appears in 4624 network logon telemetry from the same attacker IP. This is the moment where the intrusion shifts from probing and ticket abuse into confirmed authenticated access.

  • EchoSentinel alerts: 859 and 860
  • Events: 4776 success, then 4624 NTLM network logon
  • Analyst meaning: recovered service/account credentials have become active access
5

Remote execution and foothold consolidation

Execution telemetry shows WmiPrvSE.exe, suspicious parent executables, cmd.exe, net.exe, and net1.exe. EchoSentinel also records a new service and a scheduled task.

  • Service-based execution: 4697
  • Scheduled task persistence: 4698
  • Process chain: GUvaKgMe.exe/sqZWiSCg.exe → cmd.exe → net.exe → net1.exe
6

Credential dumping

C:\Tools\x64\mimikatz.exe is executed. Soon after, 4663 shows that process touching lsass.exe. This is the strongest single host-level credential-dumping artifact in the evidence set.

  • Execution event: 4688 for Mimikatz
  • Credential access proof: 4663 against \Windows\System32\lsass.exe
  • Interpretation: active extraction of in-memory credentials or secrets
7

ACL abuse and privilege escalation

A high-risk 4670 alert marks permission modification. Around the same cluster, privileged logons and machine-account activity increase. This is the strongest explicit escalation indicator surfaced by EchoSentinel.

  • EchoSentinel high severity: Alert 863 / ES-SMB-003 File/share permission modified (4670)
  • Privileged logon evidence: 4672
  • Context: aligns with ACL abuse and privilege extension in the scenario chain
8

DCSync / replication-right abuse

A burst of 4662 Directory Service object-access events shows DS replication-related GUIDs. That combination is a classic DCSync logging footprint when SACLs are configured to capture it.

  • GUIDs shown include {1131f6aa-9c07-11d1-f79f-00c04fc2dcd2} and {1131f6ad-9c07-11d1-f79f-00c04fc2dcd2}
  • Interpretation: replication of protected directory data, potentially including credential material
  • Correlation: arrives after the privilege/permission abuse cluster, strengthening the case
9

Late-stage privileged operations

4648 indicates explicit credential use. Later hunt results show 4769 service ticket activity for Administrator@LAB.LOCAL, consistent with very high privilege or domain-admin-equivalent control.

  • EchoSentinel signal: Alert 870 / ES-AUTH-007 Explicit credentials used (4648)
  • Late-stage users: WIN-EVGH6IS9JPB$, Administrator@LAB.LOCAL
  • Golden Ticket note: scenario notes support it, screenshots alone do not directly prove forged-ticket persistence

Detection and Investigation Logic

Best opening pivot

Start with alert 858 because it isolates the move from generic probing into credential-access behavior. From there pivot into the surrounding 4768, 4776, and 4624 events to identify which accounts were requested, validated, and then used.

Best host pivot

Pivot on Bobo at 08:15:49. That cluster contains the compromise confirmation, the privileged logon alert, the service creation alert, the shell/tool execution sequence, and the subsequent Mimikatz activity.

Best escalation pivot

Pivot on alert 863. High-severity 4670 permission modification sits directly before the replication-style 4662 burst, which makes it the cleanest bridge into the DCSync phase.

Best practical triage flow: alert 858 → user j.smith → successful 4776 → Bobo 4624/4672 → 4697/4698 → 4688 Mimikatz → 4663 LSASS → 4670 → 4662 replication GUIDs → 4648 → Administrator 4769
